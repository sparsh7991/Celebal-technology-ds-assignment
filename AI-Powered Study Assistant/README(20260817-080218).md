# AI-Powered Study Assistant

A local AI study assistant that lets students upload PDF study material,
ask questions about it, and generate summaries, flashcards, and quizzes
grounded in the uploaded content.

## Features

-   PDF upload and text extraction with PyMuPDF
-   Sentence-based chunking with LlamaIndex `SentenceSplitter`
-   `BAAI/bge-small-en-v1.5` embeddings
-   Persistent LlamaIndex `VectorStoreIndex`
-   Query rewriting for retrieval
-   Hybrid retrieval: 60% semantic similarity + 40% lexical token
    overlap
-   Local Qwen2.5 3B generation through Ollama
-   Source/evidence information with page numbers
-   Conversation history
-   Study-event tracking
-   Summary generation
-   Flashcard generation
-   Multiple-choice quiz generation
-   Quiz attempt and score storage
-   SQLite database with SQLAlchemy ORM

## RAG Pipeline

### 1. Document ingestion

The backend accepts PDF files and extracts text page-by-page using
PyMuPDF. Each page is represented as a LlamaIndex `Document` with
metadata such as document ID, filename, and page number.

The current implementation does **not** perform OCR for
scanned/image-only PDFs. If no extractable text is found, indexing fails
with an appropriate message.

### 2. Chunking

The project uses:

``` python
SentenceSplitter(
    chunk_size=350,
    chunk_overlap=40,
)
```

This is sentence-based chunking. The overlap helps preserve context
across neighboring chunks.

### 3. Embeddings

Document chunks are converted into dense vectors using:

``` text
BAAI/bge-small-en-v1.5
```

### 4. Vector indexing

The chunks are stored in a LlamaIndex `VectorStoreIndex`, which is
persisted per document so the index can be loaded later without
rebuilding it.

### 5. Query rewriting

The user's original question is rewritten into a concise semantic-search
query. The rewritten query is used for retrieval, while the original
question is retained for final answer generation.

### 6. Hybrid retrieval

The system first retrieves at least 10 candidates using vector
similarity and then reranks them using:

``` text
Final Score =
    0.60 × semantic similarity
  + 0.40 × lexical token overlap
```

Semantic similarity captures meaning, while lexical overlap gives
additional sensitivity to specific query terms.

The highest-ranked candidates are selected for the final context.

### 7. Grounded generation

The selected chunks are passed to a local `qwen2.5:3b` model through
Ollama.

The generation prompt instructs the model to:

-   answer only from the supplied sources
-   avoid outside knowledge
-   say when the sources do not support the answer
-   keep the answer concise

### 8. Evidence

After generation, the system ranks evidence against the question and
answer and returns source information containing:

-   page
-   filename
-   score
-   relevant text

## Learning Features

### Summary

Generates concise bullet-point summaries and a revision checklist from
retrieved study material.

### Flashcards

Generates six flashcards using a constrained text format and parses them
into structured objects.

### Quiz

Generates four multiple-choice questions using a constrained format and
parses them into structured quiz objects.

Plain-text formats are deliberately used instead of relying on strict
JSON output from the small local model.

## Setup

### Requirements

-   Python 3.x
-   Node.js 18+
-   Ollama
-   Sufficient RAM/storage for the local LLM and embedding model

### 1. Clone the repository

``` bash
git clone <your-repository-url>
cd <your-repository-name>
```

### 2. Backend

Create a virtual environment:

#### Windows

``` bash
python -m venv venv
venv\Scripts\activate
```

#### macOS / Linux

``` bash
python3 -m venv venv
source venv/bin/activate
```

Install dependencies:

``` bash
pip install -r requirements.txt
```

### 3. Ollama

Install Ollama and pull the configured model:

``` bash
ollama pull qwen2.5:3b
```

The project configures:

``` text
model = qwen2.5:3b
```

and uses:

``` text
BAAI/bge-small-en-v1.5
```

for embeddings.

### 4. Start the backend

From the backend directory:

``` bash
uvicorn main:app --reload
```

Health check:

``` text
GET /api/health
```

Expected:

``` json
{
  "status": "ok"
}
```

### 5. Start the frontend

From the frontend directory:

``` bash
npm install
npm run dev
```

The frontend uses the local Next.js development server, normally:

``` text
http://localhost:3000
```

## Why These Technologies?

### Why RAG?

The student's uploaded notes/textbooks are specific knowledge sources.
RAG retrieves relevant passages from those documents and supplies them
to the LLM so answers can be grounded in the study material.

### Why BGE-small?

BGE-small provides a lightweight embedding model suitable for a local
application where computational resources matter.

### Why hybrid retrieval?

Semantic similarity understands meaning, while lexical overlap adds
sensitivity to specific words. Combining both helps reduce cases where a
generic semantically related chunk outranks a chunk containing the
specific terms requested.

### Why SQLite instead of MongoDB?

The current application is local/single-user oriented and stores
structured relational data. SQLite avoids the need for a separate
database server and is sufficient for the current requirements.

MongoDB could be considered for a future distributed or larger-scale
deployment where a document-oriented database provides additional
benefits.

## Evaluation

The project contains a lightweight local RAG smoke-evaluation endpoint
reporting:

-   `retrieval_hit_at_5`
-   `answer_faithfulness`

The current implementation explicitly treats this as a smoke evaluation
rather than a formal benchmark. A formal evaluation should use
human-verified questions, expected evidence, and reference answers.

## Limitations

-   Scanned/image-only PDFs are not OCR'd by the current implementation.
-   Local LLM performance depends on available hardware.
-   The evaluation is a lightweight smoke test rather than a formal
    benchmark.
-   The current design targets local/single-user usage rather than
    large-scale production deployment.
